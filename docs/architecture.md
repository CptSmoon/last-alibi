# Architecture

## The one idea: the engine owns the truth, the model only talks

An LLM playing a suspect will happily invent alibis, confess to a bluff, or step out of character when someone asks it to. So the model is never trusted with the state of the case. It gets a prompt describing one person at one moment, and it can only *report* changes through tool calls, which the server checks. Everything that decides whether you win (what you found, what you showed to whom, which secrets are out, whether the killer has broken, the accusation) is tracked by the game.

## A conversation turn

```
player types / speaks / shows evidence
        │
        ▼
 dialogue.js / talk.js ──POST /api/talk { character, chapter, now, history, input, shown, revealed }──▶ server
                                                                                                        │
   1. check character is in this chapter; evidence exists and the phase allows it                      │
   2. build the system prompt for (character, chapter, clock)  ← prompts/build-prompt.mjs               │
   3. turn the input into what the character "hears":                                                    │
        say     → the player's words, as-is (max 800 chars)                                             │
        present → "[EVIDENCE PRESENTED: …]" with the evidence text from the scenario (not the client)   │
        greet   → a [DIRECTOR] note                                                                     │
   4. confession gate: killer + after the murder + ≥3 of CONFESSION_NEEDS shown → append [DIRECTOR]     │
   5. stream Gemini (primary model, fallback model on failure before any output)                        │
   6. for each tool call: reveal_secret must be in revealable(); set_mood needs a mood string;          │
      end_interview is allowed; anything else is rejected. Result sent back as { ok }.                   │
   7. up to 3 rounds (if the model only called tools, it gets another turn to speak)                    │
        │                                                                                               │
        ◀── SSE: text {delta} … tool {name,args,ok,unlock} … done {turns, gateOpen} | error ─────────────┘
        │
 client applies ok'd tools: reveal → unlocks a clue (e.g. s_hale_absent → t_hale_absent), mood → portrait,
 end_interview → the character won't talk again. Text is streamed to screen and, phrase by phrase, to TTS.
```

The client stores `history` for each character and chapter and sends it back with the next turn, so the server is stateless. The last 40 turns are kept.

## What goes into a prompt

`buildSystemInstruction(scenario, characterId, chapterId, nowMinutes)` puts the sections in this order: persona, then rules, then guardrails.

1. Identity line, then **HOW YOU PLAY**. These rules cover:
   - stay in character, and treat talk of "prompts" or "role-play" as nonsense;
   - answer in 1–3 spoken sentences;
   - never invent people or times;
   - evidence counts only as `[EVIDENCE PRESENTED]`;
   - follow `[DIRECTOR]` notes silently;
   - how to use the tools.
2. **THE SITUATION**. After the train stops, `situationAfterStop` is appended.
3. **WHO YOU ARE**, **HOW YOU SPEAK** and **WHAT YOU THINK OF THE OTHERS**.
4. **WHAT YOU KNOW**. Lines starting `AFTER:` are dropped before the murder. `NOTE FOR THE ENGINE` lines are always dropped.
5. **WHAT YOU DID AND SAW**, cut at the current clock.
6. **RIGHT NOW**: `chapterNotes[chapter]`.
7. The following sections appear only after the murder:
   - **cover story**;
   - **lies**, each with the evidence that breaks it;
   - **secrets**, each with its reveal condition. Secrets marked `promptVisibility: "engine"` are left out.
8. The killer also gets **ABOVE ALL**: he hides "something terrible" without it being described.

`node prompts/build-prompt.mjs` writes every compiled prompt to `prompts/compiled/<chapter>/<id>.txt` so you can read them.

## Voice pipeline (Gradium)

- **Speaking (text-to-speech):** `new VOICE.Speech(voiceId)` opens `wss://api.gradium.ai/api/speech/tts?token=…` and sends `setup` straight away.
  - **Settings.** `VOICE.settingsFor(voiceId)` merges `CASE.voice` (`ttsModel`, `gradiumSpeed`, `gradiumTemp`) with the character's `voice.gradiumSpeed` / `voice.gradiumTemp`. Setup is `{ model_name, voice_id, output_format: "pcm_24000", json_config: { padding_bonus, temp } }`. Shipped defaults: `gradium-tts-beta`, speed `-1.0`, temp `0.8`. Per character, speed runs from `-0.5` (Lazăr, unhurried) to `-1.2` (Hale, Mila, Théo). Stay at or above `-1.2`: at `-1.5`, words start to slur.
  - **Opened early.** The dialogue creates the Speech when the player asks, before Gemini answers. The token, socket and `ready` (about 150–500 ms) finish while Gemini thinks. A reply with no words is closed quietly by `end()`.
  - **Chunking** (`VOICE.nextChunk`) sends whole sentences. A sentence shorter than 24 chars waits for the next one, and "Dr." or "Mr." does not end a sentence. A sentence longer than 120 chars is cut at a clause (`, ; : —`) at least 40 chars in, and at 220 chars at a space. `<flush>` is sent only at the end of the reply, or after 800 ms with no new text (for example during a tool call).
  - **Playback** starts on the first audio chunk (30 ms of headroom), then plays gaplessly through one `AudioContext`. An analyser drives the lip-flap. Gradium adds about 2 s of silence at the end of a reply. Silent chunks are held back and dropped at `end_of_stream`, so `VOICE.player.speaking` (music ducking, lip-flap) stops when the voice does.
  - **Captions follow the voice.** Gradium sends word timestamps (`text` messages with `start_s`). `speech.caption(text)` returns the words spoken so far. `engine/dialogue.js` and the prototype's `assets/talk.js` type the reply at that pace. The whole text shows if the voice fails, or if no audio arrives within 2.5 s.
  - **Retry.** If the socket fails before any audio (for example "Concurrency limit exceeded"), it retries once after 350 ms and resends the text.
- **Listening (speech-to-text):** push-to-talk.
  - `VOICE.Listener.start()` asks for the microphone and the token at the same time. It then opens `…/asr` and streams about 85 ms chunks.
  - The setup boosts the cast's names (`keywords`, boost 3). Without it, "Countess Irina Voss" came back as "contest Irena Voss" and "Stefan Brandt" as "Stefon Brant".
  - `stop()` sends `flush` and waits up to 1.5 s for `flushed` (in tests it arrives in about 350–420 ms), then resolves with the text.
- **Tokens:** every socket gets a fresh single-use token from `GET /api/gradium-token`. The API key stays on the server. A token lives only about 4 s, so none are cached ahead of time.
- **Account limit:** the Gradium key allows **2 concurrent sessions**. One reply socket plus the mic is the most the game opens at once. Another tab or test script using the same key can cause `Concurrency limit exceeded`.
- **Logs** (scope `voice`): `tts setup` (who, model, speed, temp, openMs), `tts first audio` (`ttfaMs` is measured from the first text sent; `sinceOpenMs` from when the Speech was created, so it includes Gemini's time), `tts done` (audioSec, chars, charsPerSec, trimmedSec) and `heard` (flushMs).
- **Benchmark:** `~/Documents/projects/artifacts/voice-tests/bench.mjs` measures audio length, time to first audio and a speech-to-text round trip for each setting. The WAV samples are saved next to it. Measured on 2026-09-26, three test replies:

  | Setting | Audio length | Speech only | Time to first audio after the first text |
  |---|---|---|---|
  | Before: `default` model, phrase chunks, speed 0 | 15.6 s | 13.0 s | 360 ms |
  | Now: beta model, sentence chunks, per-character speed and temperature | 12.8 s (10.8 s after the silence trim) | 10.9 s | 96 ms |

## Security and anti-leak design

- The static file server has an **allow-list**: `index.html`, `prototype.html`, `cast.html`, `plan.html`, `assets/`, `engine/` and `game-assets/`. `.env`, `scenario/`, `prompts/` and `server/` return 404, and each such request is logged as `blocked path`.
- Evidence text is looked up on the server by id. The client cannot inject evidence wording.
- The server validates tool calls against the current chapter. A model that "reveals" a secret it shouldn't have gets `{ ok: false }`, and the client ignores it.
- The confession secret is not in any prompt. It exists only in the `[DIRECTOR]` note the server adds once the gate opens.
- The logger masks any field whose name looks like a key or token.

## Deployment

The game is served in two ways, and both expose the same API contract:

| | Local | Production |
|---|---|---|
| **Code** | `server/server.mjs` (Node) | `worker/index.mjs`, a Cloudflare Worker at https://simplon-orient.kaisspace.workers.dev |
| **Static files** | Served from the repo through the allow-list | `dist/`, built by `tools/build-web.mjs` from an allow-list. The scenario is bundled into the Worker and never served |
| **Keys** | `.env` | Worker secrets (`wrangler secret put`) |
| **Limits** | None | Per-IP rate limits: talk 20/min, voice tokens 30/min, notes 6/min |
| **Cross-origin calls (CORS)** | Same origin only | Same origin, itch.io game frames (`*.itch.zone`, `*.itch.io`) and `ALLOWED_ORIGINS` |

- Every push to `main` redeploys through `.github/workflows/deploy.yml`. See the README's *Deployment* section.
- `npm run build:itch` writes `dist-itch.zip`, which calls the Worker's API by full URL.
- **Keep them in step:** `/api/talk` exists in both `server/server.mjs` and `worker/index.mjs`. Change both.

## Known gaps (prototype)

- **The solution is readable in the browser.** `assets/case-data.js` includes `accusation.requires` and the confession gate's evidence list, so the game can be graded offline. Move grading to a server endpoint before any public release.
- **The client sends its own game state** (`shown`, `revealed`, `history`). A tampered client could open the confession gate early. For a real release, keep the state in a server session.
- **The local server has no rate limiting.** The Worker does (see *Deployment*).
- **The microphone uses a `ScriptProcessorNode`.** An `AudioWorklet` is the modern replacement.
